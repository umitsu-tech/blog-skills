# review-blog（投稿前レビュー）

文体ルールのファイルと、自分の過去記事2〜3本を必ず読んでからレビューする作りです。指摘は「機械的な修正（考えなくていい）」と「判断してほしい提案（考えるところ）」の2層に分けて出てきます。

![review-blogの仕組み](../images/review-blog-flow.png)

## 何を読んでからレビューするか

1. 設定値「文体ルールのファイル」。自分の書きっぷりを言語化した Markdown で、私のものは [skills/review-blog/references/my-style.md](../skills/review-blog/references/my-style.md) です
2. 記事リポジトリの `published/` にある過去記事。`scripts/pick-references.sh`（POSIX sh）が 5KB 以上の記事をファイル名でジャンル（トラブルシュート系、実装・手順系、解説系）に分けて新しい順に並べ、スキルがレビュー対象とジャンルが近いものを2〜3本選んで読みます
3. [criteria.md](../skills/review-blog/criteria.md) の観点と [examples.md](../skills/review-blog/examples.md) の良い例・悪い例

過去記事を読ませるのは、「一般的に良い文章」ではなく「自分の普段の書き方」に揃える方向で提案させるためです。

## 出力

詳細レポートを下書きの隣に書き出し（`foo.md` なら `foo.review.md`）、ターミナルには高優先度の指摘と件数だけを出します。指摘には通し番号が付くので、「4だけ適用して」のように番号で採否を伝えられます。

## 改善ループ

レビュー対象に繰り返し現れるのに文体ルールに書かれていない癖や、レビュー後に受け入れられなかった指摘を見つけると、文体ルールへの追記を1行の形で提案します。勝手には書き換えません。
